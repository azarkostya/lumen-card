Сверка по истории (`cfe0047` → HEAD): механика показа логотипа не менялась ни разу — `write()` ставит `background-image` и класс `lumen-hero--logo`, класс прячет текстовый `__title`; порядок вызовов тот же: `show()` → `render(модель без деталей, swap=true)` → `loadDetails` → `render(модель с деталями, false)`. **Изменился режим движения.** В первой версии автодетекта не было (`motionModeFor(stored, platform)` давал `lite` только Tizen/webOS; введён в `680daef`, порог замера — Task 40), и Android-ТВ с «Авто» работал в `full`. В `full` первый `write()` откладывается на `SWAP_MS = 180` под анимацию ухода текста, а детали для уже виденной карточки приходят из кэша Lampa синхронно (`life: DETAILS_LIFE`; комментарий у `render()` это прямо описывает) — отложенный `write()` берёт `state.model` **уже с логотипом**, и видимый вывод один. В `lite` `write()` мгновенный: сначала текст без деталей, через сеть/кэш — второй `write()` с логотипом. Это и есть «на ходу».

Почему телевизор в `lite`: `weakHardware()` не сработал (4 ядра, `deviceMemory` не отдан), значит — вердикт по замеру `src/68_perf.js`: три замера времени до первого кадра (`track('card')` на `full:complite`, `track('main')` на монтировании героя), медиана ≥ `SLOW_MS = 400` → `lite`, записывается в Storage и снимается только после `GOOD_RUNS = 5` хороших запусков подряд. С карточкой длинного сериала на 2 fps (раздел 0) вердикт `lite` гарантирован. То есть **`lite` — не свойство железа, а следствие тормозов карточки (Task 67) плюс инерция вердикта**, и он тянет за собой сразу три жалобы: логотип на ходу, рулетка без спина, ни одного кроссфейда.
