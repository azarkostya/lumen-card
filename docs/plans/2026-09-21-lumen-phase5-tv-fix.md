**Tech Stack:** ES5, Lampa 3.3.4 (`vendor/lampa`), тесты `node --test "test/*.test.mjs"`, сборка `node scripts/build.mjs`, `node scripts/es5check.mjs`. `node` в Bash: `export PATH="$PATH:/c/Users/azark/AppData/Local/Programs/nodejs"`.

**Решение по стартовому состоянию:** подписи там намеренно остаются за кромкой — в старте фокус на герое, ряд «выглядывает» постерами (паттерн Apple: «allow offscreen content to peek in from the edge»). Жалоба пользователя была по фото, где карточка увеличена, то есть фокус **в ряду** — это поднятое состояние, и оно после правки укладывается с запасом 25 px. Постер в старте виден целиком, за кромку уходит только текст.

**Почему 9.52em, а не 11.4:** сетка Apple (HIG Layout → Grids) даёт 7 колонок по 217 физ. px = 9.52em при зазоре 40 px; 6 колонок (11.4em = 260 px) с подписями по 23 px в поднятом состоянии не помещаются (550 > 540). То есть ширину диктует арифметика, а не вкус.

**Почему `ROW_FOCUS` 1.10, а не 1.06:** Apple Top Shelf даёт 1.089-1.14, AOSP `focusedScale` = 1.1 (`docs/research/2026-09-21-tv-design-specs.md`). Зазор под заголовком ≥ рост постера вверх: 162.9 × 0.10 = 16.29 px = 1.43em < 1.5em ✓.

### Поправка к Task 51 (раскладка)
Ширина карточки `11.4em` = ровно 6-колоночная сетка Apple (260 px при зазоре 40 px), а `9.6em` ≈ 7-колоночная (217 px = 9.52em). Обе — эталонные; выбираем **7 колонок: `ROW_CARD_W = 9.52`, зазор между карточками `1.75em` (40 px)** вместо нынешних ~33 px. Масштаб фокуса **не снижать до 1.06**: Apple/AOSP — 1.10-1.14; держать `ROW_FOCUS = 1.10`, а зазор заголовка считать от него (`≥ 217×1.5×0.10 = 32.5 px = 1.43em` → `round2(1.5 × scale)`). Подписи при этом поднимаются до минимума tvOS (Task 63), что добавляет ~3 px высоты — пересчитать тест «низ подписи ≤ 540».
