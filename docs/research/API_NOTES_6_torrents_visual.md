# Lampa API Notes 6 — визуальный аудит пути через TorrServer (живая Lampa 3.3.4)

Продолжение `API_NOTES_5_torrents.md`. Там — разбор компонентов и рецепты по исходникам/шаблонам.
Здесь — те же 12 экранов пройдены вживую в браузере (`http://localhost:8766/vendor/lampa/index.html`, 1920×1080,
плагин Lumen Card выгружен), с реальными `getComputedStyle`, поведением пульта и починкой нерабочих рецептов.

Карточка-опора: «Дюна: Часть вторая» (`id:693134, method:'movie'`), открыта через
`Lampa.Activity.push({url:'', title:'Дюна', component:'full', id:693134, method:'movie', card:{id:693134, source:'tmdb'}, source:'tmdb'})`.

**Базовая единица на этом экране**: `1em ≈ 22.811px` при 1920×1080 (корневой `font-size`, который сама Lampa
выставляет для десктоп-брейкпоинта `size--normal`). Все px ниже — реальные computed-значения; в скобках даю
em-эквивалент (÷22.811), когда он «круглый» и совпадает с CSS-исходником из `API_NOTES_5`.

**Важно для дизайна**: это ЧУЖОЙ базовый em, не совпадающий с допущением Lumen-токенов
(«1em = 16px», см. `docs/plans/2026-09-15-lumen-card.md` §0.4). Один и тот же px-размер в двух системах — это
разные em. При переносе токенов на эти экраны либо пересчитывать px→em по коэффициенту Lampa (22.811px / 16px ≈ 1.426),
либо жёстко задавать px внутри зоны действия правил.

## 0. Методологические находки (пригодится, если кто-то продолжит этим же способом)

1. **Viewport сбрасывается посреди сессии.** Один раз между вызовами `1920×1080` незаметно съехал к `301×632`
   (мобильная раскладка) без явной команды с моей стороны — часть замеров для «TorrServer не задан» пришлось
   переснимать. Перед каждым блоком замеров стоит на всякий случай перепроверять `window.innerWidth` и
   перевызывать `resize_window`, а не полагаться, что размер держится весь ход сессии.

2. **OK/Enter не проходит одним `keydown`.** В `app.min.js` (`init$1o`) слушатель `keydown` только взводит
   800-мс таймер долгого нажатия (`isEnter(code)` → `timer$9=setTimeout(...,800)`), а сам `Controller.enter()`
   вызывается **на `keyup`**, и только если `longpress` не успел выставиться:
   ```js
   window.addEventListener('keyup', function (e) {
     clearTimeout(timer$9); ...
     if (!longpress) {
       if (isEnter(keyCode(e)) && !e.defaultPrevented) { Sound$1.play('enter'); ...; Controller.enter(); }
     } else longpress = false;
   });
   ```
   Рецепт из задания (один `dispatchEvent(keydown)` с переопределённым `keyCode`) отлично двигает фокус
   (37/38/39/40 читаются прямо в generic keydown-broadcast), но для 13 (OK) нужна ПАРА событий:
   ```js
   window.press = async function(code){
     function fire(type){ var ev=new KeyboardEvent(type,{bubbles:true});
       Object.defineProperty(ev,'keyCode',{get:function(){return code;}}); document.dispatchEvent(ev); }
     fire('keydown'); await new Promise(function(r){setTimeout(r,40);}); fire('keyup');
   };
   ```
   40 мс между ними — с запасом меньше 800-мс порога долгого нажатия. С одним `keydown` OK попросту не
   срабатывает (первая попытка на Select «Источник» молча ничего не сделала).

3. **Руками добавленные `.torrent-item`/`.torrent-file`/`.torrent-serial` не понимают `hover:long`.**
   Обработчик долгого нажатия вешается компонентом именно в момент его собственного `append()`
   (`item.on('hover:long', function(){ ... Select.show(...) })` внутри `torrents.js`/`torrent.js`).
   Если элемент вставлен в DOM напрямую (как в мок-рецептах §2.8/§4.6 из `API_NOTES_5`), клавиатурная
   навигация (Controller/Navigator, основана на классе `.selector`) работает нормально, а вот `hover:long`
   и `hover:enter` — нет, они не были никогда забинжены. Рабочий обход: вызвать тот же `Select.show(...)`,
   что вызвал бы обработчик, вручную — код подсмотрен прямо в `app.min.js` (в `API_NOTES_5` он был сокращён
   многоточиями) и приведён ниже в §2.7 и §4.4.

4. **Нативный `Element.append()` теряет все узлы шаблона, кроме первого.** `Modal.update()` в итоге зовёт
   `_scroll.append(new_html)`, а внутри — `body.append(object)` на сыром DOM-узле
   (`body = html.querySelector('.scroll__body')`), не через jQuery. Шаблон `torrent_nohash` (§3.5) — это
   jQuery-коллекция из 3 узлов верхнего уровня (`.error` + текстовый узел + `.torrent-error`). Проверено
   изолированно:
   ```js
   var test = $('<div id="a">A</div><div id="b">B</div><div id="c">C</div>');
   var host = document.createElement('div');
   host.append(test);
   // host.children.length === 1 — остался только #a
   ```
   Рецепт из `API_NOTES_5` §3.7 («Не удалось получить хэш») из-за этого рисует только блок `.error`,
   `.torrent-error` пропадает молча. **Рабочий вариант** — обернуть результат шаблона в один контейнер
   через jQuery (её `.append()` корректно переносит все узлы) перед тем как отдавать в `Modal.update`:
   ```js
   var tpl = Lampa.Template.get('torrent_nohash', {title:'...', text:'...', url:'...', echo:'...'});
   tpl.find('.is--torlook').remove();
   Lampa.Modal.update($('<div></div>').append(tpl));   // ключевая правка — обёртка
   ```

5. **`.selectbox`/`.modal` — одноразовые синглтон-узлы на всё приложение.** Создаются один раз и потом
   только показываются/прячутся повторными `Select.show()`/`Modal.open()`. Если для «уборки» между экранами
   сделать `$('.selectbox').remove()` (как сделал я один раз, разгребая случайно наставленный стек модалок) —
   модуль `Select` продолжает держать ссылку на уже отсоединённый от DOM узел, и ВСЕ последующие
   `Lampa.Select.show(...)` за всю оставшуюся жизнь страницы перестают что-либо показывать, без единой ошибки
   в консоли. Чинится через `Lampa.Select.render(true)` (достаёт внутренний узел модуля) и ручной
   `document.body.appendChild(el)`. Правильная уборка — `Lampa.Select.close()`/`Lampa.Modal.close()`, никогда
   `.remove()` из консоли.

6. **Кнопка «Торренты» в этой сборке скрыта по умолчанию** (`class="full-start__button view--torrent hide"`,
   контейнер `.buttons--container` тоже `hide`) — настроенных парсеров ноль, и логика показа кнопки
   (асинхронная проверка наличия раздач) никогда не снимает `hide`. Штатный путь «карточка → Смотреть →
   Select источников → Торренты» без этого недостижим. Снимается вручную:
   ```js
   $('.buttons--container').removeClass('hide');
   $('.view--torrent').removeClass('hide').addClass('selector');
   ```
   после чего `.button--play` («Смотреть») триггерит настоящий `Select.show()` с двумя пунктами.

Все 12 экранов из карты `API_NOTES_5` открыты; ниже — по одному разделу на экран, той же нумерацией.

## 2.7 / 3 (по нумерации API_NOTES_5). Меню действий на торренте (долгое нажатие)

**Рецепт (рабочий — прямой вызов, т.к. `hover:long` не биндится на впрыснутых карточках, см. находку №3;
код подсмотрен в `app.min.js`, а не только по сокращённой цитате из `API_NOTES_5`):**
```js
var menu = [
  {title: Lampa.Lang.translate('torrent_parser_add_to_mytorrents'), tomy:true},
  {title: Lampa.Lang.translate('torrent_parser_label_title'), subtitle: Lampa.Lang.translate('torrent_parser_label_descr'), mark:true},
  {title: Lampa.Lang.translate('torrent_parser_label_cancel_title'), subtitle: Lampa.Lang.translate('torrent_parser_label_cancel_descr'), unmark:true}
];
Lampa.Select.show({
  title: Lampa.Lang.translate('title_action'), items: menu,
  onBack: function(){ Lampa.Controller.toggle('content'); },
  onSelect: function(a){ Lampa.Controller.toggle('content'); }
});
```

**Раскладка/тексты**: тот же `.selectbox`, заголовок «Действие», 3 пункта без иконок:
«Добавить в «Мои торренты»» (без подзаголовка, в фокусе по умолчанию), «Пометить» (подзаголовок «Пометить
раздачу с флагом (просмотрено)»), «Снять отметку» (подзаголовок «Снять отметку с раздачи (просмотрено)»).

**Замеры**: панель та же 672px, но пункт БЕЗ иконки ниже — 672×107 (не 130, т.к. нет блока иконки 2.7em),
padding те же 34.2/45.6. Подзаголовок `.selectbox-item__subtitle` — 581×35, шрифт 25.1px/400 (1.1em), по
исходному CSS должен идти с `opacity:.7` (сам computed `color` — сплошной белый, приглушение только через
opacity элемента, не через цвет текста).

**Корень / классы**: тот же `.selectbox`. Отличить от экрана §1 можно по `active.title` (`title_action` вместо
`settings_rest_source`), НО тот же самый `title_action` + тот же голый `selectbox_item`-шаблон использует
универсальный обработчик долгого нажатия `Menu.onCreate` (генерируется в `app.min.js` для карточек/списков
по всему приложению, не только для торрентов) — различать конкретно «меню торрента» можно только по составу
пунктов (флаги `tomy`/`mark`/`unmark`), не по заголовку/классам.

**Пульт**: ↓ листает 3 пункта; OK на «Добавить в Мои торренты» вызвал бы `addToBase()` (не тестировал —
не хотел писать в реальное хранилище тестовыми данными); Назад → `Controller.toggle('content')`, шторка
закрывается корректно (проверено).

## 5. TorrServer не задан (torrent_install)

**Рецепт:**

## Итог: разница со стилем карточки Lumen (см. `docs/plans/2026-09-15-lumen-card.md` §0.4)

- **Шрифты и масштаб.** Везде по пути — системный `SegoeUI, sans-serif`, начертания только 300/400/600/700.
  Ни Unbounded, ни Golos Text, ни JetBrains Mono нигде не подключены. Плюс базовый em самой Lampa на этих
  экранах (~22.8px @1920px) не совпадает с 16px-базой, на которую рассчитаны px-значения Lumen-токенов.
- **Палитра и форма.** Фоны — нейтральный тёмно-серый (`#262829`/`#1d1f20`/`rgba(0,0,0,.2-.3)`), никакого
  угольно-чёрного `#0B0908`/`#1C1613` и акцентных цветов (Песок/Лёд/Вино/Мята) нет вообместе пути. Радиусы
  почти везде мелкие (0.3em ≈ 6.8px на карточках торрентов/файлов), тогда как у Lumen — крупные 18px на
  кнопках.
- **Язык фокуса.** На одном и том же пути минимум ЧЕТЫРЕ разных способа показать фокус: белая рамка-обводка
  через `::after` (`.torrent-item`, §2), смена фона на светлее (`.selectbox-item`, `.torrent-serial`), смена
  фона на прозрачность повыше (`.torrent-file`, §9), и инверсия чёрное-на-белом (кнопка чек-листа, §6). Ни в
  одном случае нет заливки акцентным цветом, `scale(1.06)` или фирменной тени `0 14px 40px rgba(accent,.35)`,
  которых требует стиль Lumen.
