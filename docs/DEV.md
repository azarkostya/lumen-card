# Lumen Card — для разработчика

Сборка, хосты и статистика, совместимость с Lampa, ограничения и риски на уровне кода, тест-стенд,
выпуск версии. Для зрителя — [USER-GUIDE.md](USER-GUIDE.md); установка в двух строках —
[README](../README.md). Разделы «Что умеет», «Настройки», «Каталог подборок», «Путь до плеера»,
«Главная, хаб, сетки и рулетка» и «Главное, о чём стоит знать до установки» живут в USER-GUIDE.md.

## Структура репозитория

```
lumen-card/
├── src/                  ← исходники плагина по модулям (00_head … 99_tail), строгий ES5
├── dist/lumen_card.js    ← собранный и сжатый плагин (результат scripts/build.mjs, коммитится)
├── scripts/              ← build.mjs (сборка), es5check.mjs (ES5-линт на acorn), chunks.mjs (инжект-чанки),
│                           release.mjs (проверки выпуска), stats.mjs (загрузки с jsDelivr по версиям)
│   └── lib/acorn.mjs     ← вендоренный парсер acorn 8.14.0 (MIT) для сборки и es5check.mjs
├── test/                 ← node --test: юнит-тесты модулей (3517 тестов на 1.3.1)
├── manifest.json         ← каталог подборок, тем и кадров заставки (генерируется сборкой)
├── lumen.js              ← короткий загрузчик для установки плагина по одной ссылке
├── harness/index.html    ← локальный тест-стенд с эмуляцией Lampa API
├── docs/tv-checklist.md  ← что проверить на живом телевизоре
├── docs/USER-GUIDE.md    ← справка для зрителя; docs/DEV.md — этот файл
├── CHANGELOG.md          ← что нового по версиям; выпуск проверяет scripts/release.mjs
└── README.md
```

## Хосты и статистика

- **Откуда грузится.** `lumen.js` по адресу установки отдаёт GitHub Pages. Сборку он просит с
  jsDelivr по тегу выпуска — `https://cdn.jsdelivr.net/gh/azarkostya/lumen-card@v<версия>/dist/lumen_card.js?v=<метка>`
  (версию и метку вписывает `scripts/build.mjs`). Тег неизменяем: jsDelivr отдаёт такой файл с
  `immutable` и `max-age` на год, сброс кэша не нужен, и под тегом всегда ровно сборка выпуска.
  Если jsDelivr ответил ошибкой (тег ещё не разрешён — 404; хост недоступен) или за 10 секунд так
  и не отдал сборку, загрузчик один раз берёт ту же сборку с Pages. Если jsDelivr догрузится после
  этого, второй копии плагина не будет: сборка выходит на первой строке, когда плагин уже запущен
  (`window.lumen_card_plugin`, `src/00_head.js`). Порог 10 с: сборка — ~245 КБ в сжатом виде
  (br/gzip), это ~2 с при 1 Мбит/с и ~8 с при 256 кбит/с, плюс новое соединение и разбор на
  слабом ТВ; ложный таймаут стоит только лишней загрузки того же файла, а «висящий» jsDelivr —
  не больше 10 с до старта.
  Бета (jsDelivr `@beta`), свой сервер, стенд и адрес по IP — как раньше: сборка из той
  же папки, что и `lumen.js`, теги им не нужны.
- **Приватность.** Ни счётчиков, ни идентификаторов, ни отдельных запросов «для статистики» —
  только другой адрес той же сборки. Параметры, которые Lampa дописывает к адресу плагина
  (`logged`, `reset`, `origin`, у вошедших в аккаунт — `email`), получает только Pages вместе с
  `lumen.js`; дальше, на jsDelivr, загрузчик их не передаёт — в адресе сборки только версия и метка.
- **Статистика.** `node scripts/stats.mjs` (или `--period week|month|YYYY-MM`) — из публичного API
  jsDelivr (`data.jsdelivr.com`, без ключей): сколько раз отдана `dist/lumen_card.js` по версиям,
  за 7 дней, за период и по дням. Это примерно «устройство × версия», а не люди: адрес версии
  браузер держит в кэше, и повторный хит бывает, только когда файл вытеснен из кэша или Lampa
  переустановили. Ветка `main` — устройства, где Lampa запустила плагин из своего кэша (Pages не
  ответил), и проверки выпуска; `beta` — бета (старая ветка `feat/lumen-v2` в сводке остаётся строкой «feat/lumen-v2»). Последние 1–2 дня jsDelivr ещё не
  посчитал. У Pages статистики нет.

## Что рисуется и откуда берутся данные

| Элемент | Источник |
|---|---|
| Бэкдроп | `Lampa.Api.img(movie.backdrop_path, 'w1280')`, фолбэк `movie.background_image`. Если ничего нет или картинка не загрузилась — процедурный CSS-градиент (3 варианта, выбор по `movie.id % 3`) |
| Мета-строка | год из `release_date`/`first_air_date`, страны из `Lampa.TMDB.parseCountries()`, хронометраж из `runtime`, для сериала — `number_of_seasons`/`number_of_episodes`, качество из `release_quality`/`quality`, жанры из `genres`, возраст из `Lampa.TMDB.parsePG()` |
| Таблица «ПОДРОБНО» | Только то, чего нет в мета-строке: оригинальное название, полная дата премьеры, создатель сериала (`created_by`), бюджет фильма (`budget`) |
| Заголовок | `{title}` из шаблона. Логотип фильма (`images.logos` из ответа `Api.full`, своего запроса к TMDB нет; язык интерфейса → английский → без языка) — и в герое главной, и в шапке карточки (настройка «Логотип в карточке», Дополнительно… → Оформление). Адрес логотипа у обоих экранов один (с `d085217` размер файла — по настоящей ширине логотипа на экране, `logoBox`), поэтому при переходе с главной он берётся из кэша браузера. В карточке пока исход логотипа неизвестен, заголовок скрыт, но не дольше 0.6 с (`TITLE_WAIT`, `src/48_hero.js`); не доехал — текст до конца показа, поздний логотип его не подменяет. В герое главной с `9604e7a` пустого ожидания нет: логотип в памяти — логотип, иначе сразу текст (0.6 с ждёт только первый вывод после открытия главной, всем скрытым блоком текста). Нет логотипа — двухуровневое название текстом |
| Описание | Ряд описания Lampa целиком (`movie.overview`) — в шапке карточки его нет, чтобы один текст не стоял на экране дважды |
| Рейтинги | `.rate--tmdb` / `.rate--imdb` / `.rate--kp` — заполняет сам движок Lampa. IMDb и КП показываются, только если Lampa их прислала (либо КП приходит вместе с отзывами по ключу) |
| «Продолжить» | `Lampa.Timeline.view(Lampa.Utils.hash(...))`. Для фильма — хэш `original_title`. Для сериала перебираются сезоны 1…`number_of_seasons` (макс. 10) × серии 1…30 и выбирается запись с самым свежим `updated` |
| Франшиза | `collection/{id}` по `belongs_to_collection` (кэш 7 дней): номер части, отметка просмотренного, «Вы здесь», «Дальше» |
| Ключевые слова (темы атмосфер) | `keywords.results` (movie) / `keywords` (tv) из того же запроса деталей, что и остальное |
| Цвет фона от кадра | `Lampa.TMDB.image('t/p/w185' + poster_path)` (с `crossOrigin="anonymous"`, поставленным до `src`) → `canvas 16×16` → двенадцать корзин оттенка, побеждает самая весомая. Не отдал пикселей — тихий фолбэк на акцент из настроек; чем именно кончилась попытка, показывает строка отладки. Попытка одна, запрос без ответа отпускается через 6 с. Прокси TMDB без `Access-Control-Allow-Origin` при `crossOrigin="anonymous"` даёт не `SecurityError`, а ошибку загрузки; второй попытки прямым адресом `image.tmdb.org` в обход прокси пользователя с `a4b8cf0` нет. Цвет фильма считается один раз и держится по «источник:тип/id» (`LC.accent`, до 200 фильмов; CUB и карточка без источника — те же id TMDB), расчёты одного фильма в пути склеиваются, соседей фокуса считает заранее дорожка `src/58_prefetch.js` (по одному, в `requestIdleCallback`, повторы — по тому же ключу; после отказа чтения — до первой удачи не считает). Цвет фона рядов — `LC.color.rowsTint`: оттенок той же доминанты, насыщенность .35–.6, светлота .18 по HSL, опускается, пока подпись `P.soft` не держит 4.5:1 на белом кадре. С раунда C (C3) доминанта главной — нижняя половина кадра героя: `Lampa.TMDB.image('t/p/w300' + кадр)` с `crossOrigin`, заказ — в миг выбора кадра (`LC.accent.prepareFrame`), параллельно с `w1280`; ключ кэша — `'frame:' + путь`; цвет фильма решается один раз (низ кадра, если посчитан к тику кадра, иначе постер w185). С `bdfcb0e` подложка героя грузит тот же файл `w300` в том же режиме CORS (`LC.accent.frameCors()`: с CORS, пока цвет читает кадры, иначе без) — на стенде двойных загрузок `w300` за прогон серий 7 → 0–1; тот же цвет низа кадра красит затемнение фона подборок (`ScreenStage`) |
| Отзывы Кинопоиска | `kinopoiskapiunofficial.tech` с ключом пользователя (заголовок `X-API-KEY`): `films?imdbId=…` → `kinopoiskId`, затем `films/{id}/reviews`. До 12 отзывов, число в заголовке — `total` ответа. Кэш 24 ч (ключ `lumen_rv_<imdbId>`), «отзывов нет» — 2 ч |
| Кадры заставки | Каталог плагина (`ambient`) или кадры открытой карточки. Размер выбирается по ширине экрана в физических пикселях: `original` только выше Full HD (`w1280`, пока ширина × 0.85 не превысила 1920), тот же порог, что у кадра карточки и кадра героя |

**Никаких выдуманных данных.** Чипы, которых нет в дизайн-макете как реальных полей
(«СМОТРЯТ 4.1K», «HDR10», «ATMOS», «RUS · ENG»), не рисуются — у Lampa нет для них источника.

## Совместимость

- **JS**: строгий ES5 — `var`/`function`, без стрелок, `let`/`const`, шаблонных строк, классов,
  spread, `Object.assign`, `Array.prototype.find`/`includes`. Работает на webkit Smart TV 2016 г.
  и Android 4.1 webview.
- **CSS**: без CSS-переменных в качестве механизма темы — акцент подставляется в CSS **литералом**
  при генерации `<style id="lumen-card-css">`, поэтому тема работает даже там, где `var()` не
  поддерживается. Флексбокс продублирован префиксами `-webkit-box` / `-webkit-flex`. Не
  используются `inset` и `:has()` — их нет в браузерах телевизоров 2016–2019 годов.
  Исключение у кадра героя одно: `object-fit` (есть с Chrome 32 и Android WebView 4.4.3 — на
  webview Android 4.1 кадр растянется без обрезки). Маски `-webkit-mask-image` у левого
  затемнения с `28f5072` нет: оно само радиальный градиент (`-webkit-radial-gradient` и
  `radial-gradient`), затухающий к нулю без кромки. На слое автотрейлера маски с волны 3 тоже
  нет: низ ролика растворяет то же затемнение слоя кадра, что и статичный кадр, — обычные
  градиенты поверх `iframe` YouTube. На живом телевизоре это не проверялось — см.
  `docs/tv-checklist-archive-2026-09.md`, раздел 7, пункт 5. Второе исключение (с `9604e7a`) — обрезка ленты рядов
  главной `overflow:clip` с `overflow-clip-margin:content-box`: движок без них правило игнорирует
  или режет по `padding-box`, то есть как прежде (стенд — Chromium 148, ТВ пользователя — 153;
  на ТВ глазами ещё не проверено).
- Внешние адреса, к которым плагин обращается помимо самой Lampa:
  - GitHub Pages (`azarkostya.github.io`) и jsDelivr (`cdn.jsdelivr.net` — сборка стабильной
    версии по тегу, запасной адрес загрузчика и бета) — сам плагин и каталог подборок (раздел
    «Хосты и статистика»);
  - Google Fonts (`fonts.googleapis.com`) — шрифты плагина, `<link>` отключается значением «Как в
    Lampa» у пункта «Шрифт» (Настройки → Lumen Card → Внешний вид → Шрифт);
  - YouTube (`youtube.com`, `youtube-nocookie.com`) — трейлеры в `iframe`;
  - `kinopoiskapiunofficial.tech` — отзывы и рейтинг Кинопоиска, только с ключом, который
    пользователь ввёл сам;
  - картинки и данные TMDB — только через прокси Lampa, напрямую к TMDB плагин не ходит.
- Весь код обёрнут в `try/catch` по ключевым местам: исключение в отрисовке не ломает карточку.
  Оригинальный шаблон сохраняется при старте и возвращается, если подмена шаблона упала.
- Все слои плагина (частицы, заставка, слой перехода рулетки, мини-карта) живут в собственных узлах и снимаются
  при смене экрана и при выключении плагина; ни один из них не перехватывает клавиши — единственное
  исключение — первое нажатие, закрывающее заставку.

### Что сохранено из оригинального шаблона `full_start_new`

Все узлы и классы, на которые опирается `src/components/full/start.js` и его модули:

`.full-start-new__title`, `__head`, `__details`, `__reactions`, `__tagline`/`.full--tagline`,
`__buttons`, `.buttons--container`, `.button--play`, `.button--book`, `.button--reaction`,
`.button--subscribe`, `.button--options`, `.view--torrent`, `.view--trailer`,
`.rate--tmdb`/`.rate--imdb`/`.rate--kp` с вложенными `div`, `.full-start__pg`,
`.full-start__status`, `.tag--year`, `.tag--time`, `.tag--quality`, `.tag--episode`,
`.is--serial`, `img.full--poster` внутри `.full-start-new__poster`, все языковые ключи `#{...}`.

SVG кнопок скопированы **побайтово** из оригинала — `start/buttons.js` хэширует `outerHTML`
кнопки для механизма «приоритетной кнопки», и любое изменение разметки сбросило бы сохранённый
приоритет.

Все кнопки остаются `.selector`, поэтому `Controller.collectionSet(this.html)` собирает их как
обычно и навигация пультом не ломается.

### Что скрыто (узлы остаются в DOM)

- `.full-start-new__left` с постером — в дизайне постера нет (но `img.full--poster` на месте,
  `poster.js` вешает на него `onload`);
- `.full-start-new__head` и `.full-start-new__details` — вместо них рисуется своя мета-строка
  (скрываются только после успешной сборки меты: если сборка упала, показывается оригинал);
- `.full-start-new__tagline` — нет в дизайне;
- `.full-start-new__reactions` — строка со счётчиками реакций; **кнопка** `.button--reaction`
  продолжает работать;
- `.full-start__pg` внутри строки рейтингов — возраст переехал в мета-строку;
- `.tag--year`, `.tag--time`, `.is--serial` — в служебном скрытом контейнере `.lumen-keep`;
- родной фон Lampa `.full-start__background` — получает класс `lumen-off`, вместо него рисуется
  свой полноширинный слой `.lumen-backdrop`.

## Ограничения и известные риски (для разработчика)

### Остальное

1. **IMDb и КП рейтинги.** Поля `movie.imdb_rating` / `movie.kp_rating` заполняются только при
   настроенном парсер-сервере или CUB-аккаунте. На «голом» TMDB их нет — чипы не появятся.
   Это не баг плагина: он лишь стилизует узлы, которые заполняет сама Lampa.
2. **Шрифты требуют интернет.** Google Fonts грузятся с `fonts.googleapis.com`. Если TV без
   доступа или провайдер режет домен — выберите «Настройки → Lumen Card → Внешний вид → Шрифт →
   Как в Lampa», будет шрифт самой Lampa.
3. **Языки аудиодорожек / HDR / ATMOS** из дизайн-макета не рисуются — у Lampa нет для них
   источника на этапе карточки (данные появляются только после выбора источника в плеере).
4. **Прогресс сериала** ищется перебором до 10 сезонов × 30 серий (300 обращений к
   `Lampa.Timeline.view`). Если сезонов больше 10 или серия за номером > 30 — «Продолжить»
   не покажется. Перебор нужен потому, что `Timeline.watched()` в самой Lampa ищет только
   по первому сезону.
5. **Реакции.** Строка со счётчиками скрыта (нет в дизайне). Если она нужна — уберите
   `.full-start-new__reactions` из правила скрытия в `buildCss()`.
6. **«Скрыть из рекомендаций»** убирает фильм из рядов не сразу: ряд уже построен Lampa, и карточка
   исчезнет при следующем построении — об этом плагин и говорит в уведомлении.
7. `100vh` у слоя бэкдропа и `74vh` у тела карточки завязаны на высоту окна. На нестандартных
   webOS/Tizen-обёртках с плавающей высотой viewport фон может оказаться чуть выше/ниже.
   `74vh` снимается на узком экране — там шапка карточки схлопывается по содержимому. «Узкий»
   считается в физических пикселях: порог `max-width` равен `1000 / devicePixelRatio`, поэтому
   телевизор с окном 960 CSS px при DPR 2 (растр 1920) узким не считается и держит полную
   раскладку. Заголовок карточки в этой же ветке — ступенью ниже: Title 2 вместо Title 1.
8. Слой `.lumen-backdrop` вставляется `prepend`-ом в корень компонента (`e.body`) — ровно туда,
   куда Lampa кладёт свой `.full-start__background`, и позиционируется так же (`position:absolute`).
   Если в конкретной сборке ближайший позиционированный предок — скролл-контейнер, фон при
   прокрутке карточки может не уезжать вместе с контентом.
9. **Меню по удержанию OK** дописывает пункты в штатное меню Lampa, распознавая его по содержимому.
   В сборке, где это меню собрано иначе, пункты просто не добавятся — штатное меню при этом не
   пострадает.
10. **Переход компактной шапки** анимирует `font-size`/`margin-top` — это layout-свойства
    (триггерят reflow), а не `transform`: шапка должна реально уменьшиться в высоте, чтобы ряд
    описания/серий под кнопками поднялся на освободившееся место. Анимация включена только в
    режиме «Полные».

### Проверено по исходникам Lampa

- `SettingsApi.addParam` с `type: 'select'` и `values: {ключ: подпись}` — **подтверждено**
  (`src/interaction/settings/api.js` → `Params.select(name, values, default)`).
- `onChange(value)` вызывается для `select` и `trigger` — **подтверждено**
  (`params.js` → `bind()`: `Storage.set(name, value); if(onChange) onChange(value)`).
- Значение `trigger` хранится **строкой** `'true'` / `'false'`. Плагин это нормализует в `pref()`,
  так что и булево, и строковое значение читаются правильно.
- **`Lampa.Controller.listener.follow('toggle', fn)`** — **подтверждено живьём** на локальной
  Lampa 3.3.4: при спуске по карточке стрелкой вниз `e.name` идёт цепочкой `full_start` →
  `full_descr` → `items_line`, при подъёме — обратно.
- **События активностей**: `Activity.push` не шлёт событий для покидаемой активности; `backward()`
  шлёт `start` и `archive` той, к которой вернулись, и `destroy` — удалённой. Отсюда и приём: всё,
  что принадлежит экрану (герой, метки, мини-карта), снимается по `start` той активности, куда ушли.
- **`Lampa.Keypad.listener`** — источник событий клавиш; Keypad нормализует коды пультов Samsung
  orsay/LG и троттлит `keydown` до одного раза в 100 мс. Команды `toup`/`todown` (кнопки каналов) в
  Lampa 3.3.4 не реализует ни один контроллер — их и занимает быстрый прыжок по ряду.

### Места, где остаётся неуверенность в API Lampa

- **`Lampa.Platform.screen('tv')`** — подтверждено в `src/components/full.js`, но экспорт
  `Platform` в `window.Lampa` напрямую не проверен; есть фолбэк на `window.innerWidth > 480`.
- **`Lampa.TMDB.parseCountries` / `parsePG`** — подтверждены в исходниках `full/start.js`, но
  как поля `window.Lampa` не проверены; есть фолбэки на данные фильма.
- **`Lampa.Lang.add({key: {ru, en, uk}})`** — сигнатура общепринятая, но в скачанных исходниках
  не проверялась. При отказе используется внутренний словарь плагина.
- **Порядок событий.** Отрисовка навешана и на `type: 'build'` + `name: 'start'`, и на
  `type: 'complite'` — второй раз она идемпотентна.
- **Голосовой ввод в поиске подборок** — плагин зовёт штатную `Lampa.Input.edit` с раскладкой
  `search`, в которой у Lampa есть кнопка микрофона. Работает ли она на конкретном телевизоре,
  зависит от самой Lampa и устройства — своего API плагин не заводит.

## Тест-стенд

Реальной Lampa для проверки не требуется — в `harness/index.html` собрана минимальная эмуляция
API (`Template`, `Listener`, `Storage`, `Timeline`, `Api`, `Utils`, `TMDB`, `Lang`, `Platform`,
`SettingsApi`, `Controller`) плюс ключевые правила CSS из `start_new.scss` / `full_start.scss`,
и воспроизведена логика `Start.create()` из `src/components/full/start.js` строка в строку.

Запуск:

```sh
# из корня репозитория
python -m http.server 8765
# открыть http://localhost:8765/harness/index.html
```

(Можно открыть и файлом напрямую, но тогда jQuery с CDN должен быть доступен.)

В стенде:

- переключатель **Фильм / Сериал** («Дюна: Часть вторая» и «Fallout»);
- кнопки акцента и тумблеры шрифтов / «Продолжить»;
- **← / →** — эмуляция пульта: переставляет класс `.focus` между `.selector` в ряду кнопок;
- панель **Проверки** — автоматически проверяет, что все узлы и классы, нужные Lampa,
  присутствуют в отрендеренной карточке (и в сыром шаблоне — для узлов, которые движок удаляет
  по данным: `.full--tagline`, `.tag--time`);
- блок **JS ERRORS** — ловит `window.onerror` и исключения внутри слушателей.

`Lampa.Api.img()` в стенде намеренно возвращает пустую строку (TMDB может быть недоступен),
чтобы проверялся именно процедурный фон.

## Разработка

Плагин собирается из модулей `src/NN_*.js` (по числовому префиксу) в один файл
`dist/lumen_card.js`, который и коммитится в репозиторий и выкладывается на хостинг.

```sh
# из корня репозитория

# сборка src/*.js -> dist/lumen_card.js (+ проверка синтаксиса node --check)
node scripts/build.mjs

# ES5-линт (парсер acorn на ecmaVersion: 5 + скан токенов на запрещённые ES2015+ API;
# ни одной находки быть не должно): раскладка src/ с точными координатами и dist
node scripts/es5check.mjs

# юнит-тесты (3517 на 1.3.1, 75 файлов) без браузера. Нужен каталог vendor/lampa/ (в .gitignore):
# исходники Lampa с https://github.com/yumata/lampa — собранный app.min.js (vendor/lampa/app.min.js)
# и css/app.css (vendor/lampa/css/app.css); часть тестов читает ещё lang/uk.js и
# vender/navigator/navigator.js. Без каталога они падают с ENOENT.
node --test "test/*.test.mjs"

# только проверить, что dist/lumen_card.js и метка в lumen.js не устарели относительно src/
node scripts/build.mjs --check

# отладка: ещё и dist/lumen_card.pretty.js — без комментариев, строки как в src/ (не коммитится)
node scripts/build.mjs --pretty
```

`scripts/build.mjs` пишет во временный `dist/lumen_card.tmp.js`, гоняет на нём `node --check`
и только при успехе переименовывает в `dist/lumen_card.js` — синтаксическая ошибка в одном из
модулей никогда не перезатирает рабочую сборку. Баннер в начале файла не содержит даты
(`// Lumen Card for Lampa v<версия>`, версия — из `LC.VERSION` в `00_head.js`), поэтому сборка
воспроизводима: одинаковый `src/` всегда даёт побайтово одинаковый `dist/lumen_card.js`. Та же
сборка генерирует `manifest.json` из `src/42_manifest.js`, поэтому каталог в коде и на хостинге не
расходятся.

`dist` сжат (`scripts/lib/minify.mjs`): без комментариев, отступов, пустых строк и лишних
пробелов между токенами — исходники с комментариями живут в `src/`. Имена и литералы не меняются,
переводы строк между операторами остаются (от них зависит расстановка `;`). Токены даёт разбор
acorn, а не регулярки, поэтому строки с `/*` внутри CSS, data-URI с `//` и регэкспы не страдают;
перед записью сборка сверяет поток токенов сжатого файла с исходным один в один и при расхождении
падает. Строки `dist` со строками `src/` больше не совпадают; точные координаты даёт раскладка
`src/` (баннер + модули после маркеров `/* ---- NN_имя.js ---- */`, `scripts/lib/bundle.mjs`) —
её проверяет `es5check`, её же без комментариев пишет `--pretty`. Разбор идёт с `ecmaVersion: 5`,
так что ES2015+ синтаксис бракует уже сама сборка (с координатой в `src/`), не дожидаясь
`es5check`. Сборка вписывает в `lumen.js` метку `var BUILD` — первые 10 hex sha256 от
`dist/lumen_card.js` — и `var VERSION` из `LC.VERSION` (тег, по которому загрузчик с Pages
берёт сборку с jsDelivr); `--check` ловит расхождение и того, и другого.

### Выпуск версии

Две ветки: `beta` — разработка и бета (jsDelivr `@beta`), `main` — стабильная
(GitHub Pages, адрес установки из README; бета — `https://cdn.jsdelivr.net/gh/azarkostya/lumen-card@beta/lumen.js`). Выпуск — это перемотка `main` на проверенный коммит
беты, без слияний и правок в самой `main`. Старая ветка `feat/lumen-v2` устарела — не использовать.

**Правило: бета держится не меньше 48 часов** перед тем, как `main` перематывается на её коммит
(`release.mjs` предупреждает, если коммит выпуска моложе 48 ч). Пункты настроек, меняющие поведение
самой Lampa (`lumen_tsclean`, `lumen_ts_health`, `lumen_parser_fallback`, `lumen_rowmem_bytes`,
будущие скрытие Shots и иконок шапки), обязаны быть выключены по умолчанию; единственное
согласованное исключение — `lumen_netmem`, включён по решению владельца. Список явный
(`BEHAVIOR_PREFS` в `scripts/release.mjs`), `release.mjs` сверяет его с `src/81_prefs.js`, новый
такой пункт вносится в список в том же коммите.

1. номер версии — **одно место**, `LC.VERSION` в `src/00_head.js`; баннер сборки и `var VERSION`
   в `lumen.js` сборка берёт из него сама; раздел `## x.y.z` в `CHANGELOG.md`. **Новая сборка —
   новая версия**: под тегом, который уже есть, jsDelivr навсегда отдаёт прежний `dist`;
2. `scripts/build.mjs`, `--check`, `es5check`, тесты — на том коммите, который выпускается;
   `node scripts/release.mjs` сверяет версию, баннер, раздел журнала, запасной адрес загрузчика,
   метку и версию сборки в нём, а если тег `v<версия>` уже есть на origin (до push — локальный) —
   что его `dist` тот же; origin недоступен — предупреждение «origin недоступен», повторить с сетью;
3. **сначала тег**: `git tag v<версия> <sha>` и `git push origin v<версия>` — до того, как Pages
   отдаст новый `lumen.js`, который попросит сборку по этому тегу;
4. `node scripts/release.mjs --tag --sha <sha>` — тег на origin указывает на `<sha>`, jsDelivr
   `@v<версия>` отдаёт ровно `dist` коммита (и по адресу загрузчика с `?v=<метка>`). Повторять до
   «ok»: пока jsDelivr тег не разрешил, он отвечает 404, и телевизор ушёл бы на запасной путь;
5. `git push origin <sha>:main` (только перемотка вперёд, без `--force`) и тот же `<sha>` в
   `beta`;
6. `node scripts/release.mjs --purge` (сброс jsDelivr `@main` — запасной адрес загрузчика и
   каталог; файлам тега сброс не нужен), через 2–3 минуты
   `node scripts/release.mjs --remote --sha <sha>` — Pages, jsDelivr `@main` и тег отдают ровно
   файлы коммита, в том числе сборку по тем адресам, что просит телевизор.

Пошагово, с откатом, — `docs/plans/2026-09-22-lumen-final.md`, раздел «E. Релиз 1.0.0».

### Контракт модулей

Каждый `src/NN_*.js` — фрагмент тела одной общей IIFE, которую открывает `00_head.js` и закрывает
`99_tail.js`; глобал у плагина один — `window.lumen_card` (объект `LC`), `window.LC` не существует.
Из `00_head.js` в остальные модули неявно, через общую область видимости, пробрасываются только
`LC`, `PLUGIN` и `warn` — любое другое взаимодействие между модулями идёт только через `LC.*`
(`LC.util`, `LC.pref`, `LC.lang`, `LC.progress`, `LC.seasonsWord` и т.д.), а не через голые
идентификаторы. Модуль с чистой логикой оформлен как `LC.xxx = (function () { …; return {…}; })();` —
изолирующая обёртка с явным `return`, чтобы его внутренние функции не утекали в общую область
видимости. `scripts/build.mjs` перед сборкой сверяет верхнеуровневые имена всех модулей и падает
при повторе имени между файлами.

Строки интерфейса живут только в `LC.STRINGS` (`src/80_settings.js`) и всегда в трёх языках
(ru/en/uk) — литералов на русском в коде нет; тест проверяет, что у каждого пункта настроек и
каждого значения `select` есть строка во всех трёх языках. Собственные стили плагина лежат под
своими корнями и не задевают разметку Lampa.

Модули с чистой логикой проверяются тестами напрямую через `test/_load.mjs`; модули с рантаймом —
на фейковых `$`/`Lampa`/таймерах (`test/_fakedom.mjs`). Итог — 3517 тестов (1.3.1; было 2973 на 1.0.0), которые
гоняются одной командой и обязаны быть зелёными перед каждым коммитом.
